Quero criar um módulo “Dev Marketing” (rota admin) para gerar e gerenciar links de indicação sem precisar que o indicador tenha acesso ao app. Requisitos:

1) Conceito

Marketing cria campanhas e links únicos (para influenciadores, empresas, QR de materiais, posts, etc.).

O clique não pontua nada; serve só para transportar ref até o app/site.

A contabilização acontece no backend do app quando o indicado faz cadastro + 1ª doação confirmada (Stripe).

Recompensa = 1 ponto de indicação (saldo separado dos Gritos).

2) Modelagem de dados (Postgres/Drizzle)
-- Campanha de marketing (agrupa links)
CREATE TABLE IF NOT EXISTS marketing_campaigns (
  id BIGSERIAL PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  owner_user_id UUID,                  -- opcional: responsável interno
  reward_to_user_id UUID,              -- opcional: se todos os links da campanha creditam para 1 pessoa id
  starts_at TIMESTAMPTZ,
  ends_at TIMESTAMPTZ,
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Link único de campanha (pode ou não estar atrelado a um usuário indicador real)
CREATE TABLE IF NOT EXISTS marketing_links (
  id BIGSERIAL PRIMARY KEY,
  campaign_id BIGINT NOT NULL REFERENCES marketing_campaigns(id) ON DELETE CASCADE,
  code TEXT NOT NULL UNIQUE,           -- ex: MKT-AB12CD (curto)
  medium TEXT,                         -- ex: instagram, qr_print, whatsapp
  source TEXT,                         -- ex: @influencerX, evento_Y
  utm_source TEXT,
  utm_medium TEXT,
  utm_campaign TEXT,
  max_conversions INT,                 -- opcional: teto de conversões válidas
  expires_at TIMESTAMPTZ,              -- expiração do link
  reward_to_user_id UUID,              -- se definido, credita para este usuário
  metadata JSONB,                      -- quaisquer infos extras
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  is_active BOOLEAN NOT NULL DEFAULT TRUE
);

-- Relação de indicação (já usada no fluxo anterior)
-- PENDENTE até 1ª doação -> CONFIRMADA
CREATE TABLE IF NOT EXISTS indicacoes (
  id BIGSERIAL PRIMARY KEY,
  indicou_id UUID,                     -- quem recebe a recompensa (pode vir de marketing_links.reward_to_user_id)
  indicado_id UUID UNIQUE NOT NULL,    -- indicado (só conta 1 vez)
  ref_code TEXT NOT NULL,              -- pode ser ref_code de usuário OU code de marketing_links
  status TEXT NOT NULL DEFAULT 'PENDENTE', -- PENDENTE | CONFIRMADA | EXPIRADA | INVALIDA
  criada_em TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  confirmada_em TIMESTAMPTZ,
  validade TIMESTAMPTZ NOT NULL        -- janela de 30 dias a partir do cadastro
);

-- Ledger de pontos de indicação (separado dos Gritos)
CREATE TABLE IF NOT EXISTS indicacao_pontos_ledger (
  id BIGSERIAL PRIMARY KEY,
  user_id UUID NOT NULL,               -- quem recebe o ponto
  indicacao_id BIGINT NOT NULL REFERENCES indicacoes(id) ON DELETE CASCADE,
  pontos INT NOT NULL DEFAULT 1,
  motivo TEXT NOT NULL DEFAULT 'indicacao_confirmada',
  criado_em TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (user_id, indicacao_id)
);

-- Idempotência Stripe
CREATE TABLE IF NOT EXISTS stripe_events (
  id TEXT PRIMARY KEY,
  processed_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

3) Fluxo de captura (site/app)

URLs de marketing devem aceitar ?ref={code} (onde code pode ser ref_code de usuário ou marketing_links.code).

Ao abrir com ?ref=..., salvar:

localStorage.ref_code = code

localStorage.ref_seen_at = ISODate

Não criar indicação aqui. A criação é no signup.

4) Fluxo de cadastro (signup)

No POST /api/auth/signup, se existir ref_code no request:

Verificar se ref_code pertence a um usuário (referral classic) ou a um marketing_link.

Determinar quem recebe a recompensa:

Se ref_code de usuário → indicou_id = user.id

Se ref_code de marketing_link:

Usar marketing_links.reward_to_user_id (se definido).

Caso não exista reward_to_user_id, registrar indicou_id = NULL e marcar a indicação como PENDENTE sem beneficiário; será possível atribuir depois via painel admin (ver item 6).

Criar indicacoes com status='PENDENTE' e validade = now()+30 dias.

Bloquear autoindicação (só se for referral de usuário).

5) Validação dentro do app (webhook Stripe)

No webhook de 1ª doação confirmada:

Encontrar indicacoes PENDENTE para indicado_id dentro da validade.

Checar marketing_links.max_conversions (se aplicável) e is_active/expirações.

Atualizar status='CONFIRMADA', confirmada_em=now().

Se houver indicou_id:

Criar lançamento no indicacao_pontos_ledger (1 ponto, idempotente).

Registrar stripe_events para idempotência.

6) Painel “Dev Marketing” (admin)

Criar Campanha: nome, período (start/end), status.

Gerar Links: quantidade (bulk), medium, source, utm_*, expires_at, max_conversions, reward_to_user_id?.

Exportar CSV com: code, short_url, qr_png_url, status, usos, conversoes_confirmadas.

Reatribuir beneficiário de indicações pendentes SEM indicou_id (caso marketing precise vincular depois).

Desativar/ativar link e campanha.

Métricas por campanha e por link:

cliques (frontend events), cadastros com ref, indicações pendentes, confirmações (doações), taxa de conversão, tempo médio até doação.

7) Encurtador & QR

Endpoints:

POST /api/mkt/links → cria 1..N links (retorna também short_url).

GET /l/{code} → redireciona para a landing principal com ?ref={code} e registra pageview (table mkt_clicks opcional).

GET /api/mkt/links/:id/qr → retorna PNG do QR (on-the-fly).

Opcional: tabela mkt_clicks(link_id, ts, ua, ip_hash) para relatório de cliques (sem PII).

8) Endpoints principais
# Admin (Dev Marketing)
POST   /api/mkt/campaigns
GET    /api/mkt/campaigns
PATCH  /api/mkt/campaigns/:id

POST   /api/mkt/links            # suporta bulk
GET    /api/mkt/links?campaign_id=...
PATCH  /api/mkt/links/:id
GET    /api/mkt/links/:id/qr
GET    /api/mkt/links/export.csv?campaign_id=...

# Público / tracking
GET    /l/:code                  # redirect -> /?ref=code (salvar ref no front)

# Signup (já existente)
POST   /api/auth/signup          # aceita ref_code (user ou marketing_link)

# Indicações e pontos (usuário autenticado)
GET    /api/indicacoes/minhas
GET    /api/indicacao-pontos/saldo
GET    /api/indicacao-pontos/ledger

# Stripe
POST   /api/stripe/webhook       # confirmar 1ª doação -> CONFIRMADA + ledger

9) Regras & antifraude

Autoindicação bloqueada quando o ref_code for de usuário.

Um indicado só conta para uma pessoa (constraint UNIQUE em indicado_id).

Janela de 30 dias após cadastro para contar.

Idempotência no webhook Stripe via stripe_events.

max_conversions por link (opcional).

Desativação automática quando expires_at passado.

10) Testes de aceitação

 Link/QRCode abre /?ref=CODE e salva ref em localStorage.

 Signup com ref cria indicacao PENDENTE (válida 30 dias).

 1ª doação confirmada → CONFIRMADA + 1 ponto para indicou_id (se houver).

 Reprocessar webhook não duplica (idempotência ok).

 Link expirado/inativo não cria indicação válida.

 max_conversions respeitado (quando definido).

 Relatórios por campanha e por link (cliques, cadastros com ref, conversões).
