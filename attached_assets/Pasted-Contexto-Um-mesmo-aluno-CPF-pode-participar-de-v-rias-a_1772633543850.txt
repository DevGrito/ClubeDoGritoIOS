Contexto:
Um mesmo aluno (CPF) pode participar de várias aulas no mesmo dia (ex.: Amarela 13–14, Verde 14:30–15:30, Vermelha 16–17). O aluno registra presença por aula, entrando e saindo (check-in/check-out). Não podemos ter duplicidade de presença, e os indicadores devem ser gerados automaticamente.

1) Entidade “Aula/Ocorrência” (chave do evento)

Precisamos que cada aula executada seja uma ocorrência única (uma “Aula”):

aula_id (PK)

turma_id

data

start_time

end_time

status (aberta / em_andamento / finalizada)

Regra: duas aulas no mesmo dia só são diferentes se tiverem intervalos de tempo diferentes (ou aula_id diferente). Essa é a base para evitar duplicidade.

2) Presença por aula (sem duplicidade)

Tabela/coleção de presenças deve referenciar aula_id:

presenca_id

aula_id (FK)

cpf (ou participante_id + cpf)

check_in_at (datetime)

check_out_at (datetime)

status (presente / ausente / justificativa etc.)

Chave única obrigatória:

UNIQUE (aula_id, cpf)
Isso garante: um CPF só pode ter uma presença naquela aula, mas pode ter presenças em outras aulas do mesmo dia (porque serão outros aula_id).

3) Indicadores (PEC / Inclusão / Psico)

Atendimentos (por CPF por aula):

Para cada aula finalizada:

contar presenças distintas por CPF naquela aula

atendimentos += count(distinct cpf where aula_id=... and status=presente)

Horas-aula (por CPF por aula):

Por padrão usar a duração planejada da aula:

duracaoHoras = (end_time - start_time)

horasAula += duracaoHoras * count(distinct cpf presentes)

Se houver check-in/check-out real, e quisermos precisão:

duracaoHorasCpf = (check_out_at - check_in_at)

horasAula += sum(duracaoHorasCpf) por CPF

(manter fallback para duração planejada se não houver timestamps)

4) Validação de sobreposição (opcional, mas recomendado)

Para evitar erro de cadastro (aula sobreposta na mesma turma/dia):

Impedir criar “Aula” com horário que sobreponha outra aula da mesma turma no mesmo dia.

5) API e UI

Criar endpoints de resumo por módulo:

/api/dashboard/{pec|inclusao|psico}/resumo?start=...&end=...
Retorno:

{ "atendimentos": 0, "horasAula": 0 }

Mostrar cards nas páginas dos coordenadores por módulo.

6) Critérios de aceite

João pode ter 3 presenças no mesmo dia (3 aulas diferentes) sem conflito.

Não existe duplicidade porque UNIQUE(aula_id, cpf) bloqueia repetição.

Atendimentos contam “CPF por aula”.

Horas-aula somam por aula (duração * presentes) e refletem o exemplo real.
